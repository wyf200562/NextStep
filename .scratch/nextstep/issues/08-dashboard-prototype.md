## Question

仪表盘在 v1 里到底回答什么问题、长什么样？做一个低保真、可看的原型（SwiftUI 静态页面或 HTML mockup 均可），至少覆盖：

- 首次打开 / 无数据状态。

- 临近截止的提醒区域。
- 状态分布（计数/条形/环形）与漏斗转化率，哪个值得进 P0。
- 从仪表盘跳转到申请列表/详情的路径。

使用暂定的申请状态枚举（wishlist / applied / OA / interview / offer / rejected / withdrawn），最终以 ticket 03 的领域模型为准。

输出：原型文件/链接 + 一句结论：哪些元素进 P0、哪些进 P1、哪些不做。

## Answer

采用变体 A「行动优先」。

- **IA**：底部保留独立「概览」tab（A 的结构），另设「申请」tab；不采用「D 结构 + A 块」的混合方案。独立概览 tab 随 A 进入 P0，不再作为 P1 备选。
- **P0**：
  - 顶部「今天」+「接下来 7 天」事件列表：截止与面试合并，按最近节点排序，点进申请详情。
  - 一行三个进展计数：进行中 / 7 天内截止 / Offer，点进对应筛选列表。
  - 最近更新：带状态与截止的申请清单，可进入全部列表。
  - 空状态：英雄区 +「添加第一份申请」/「去 Discover 看看」；不放 1/2/3 步骤说明（按本轮反馈）。
- **P1**：状态分布图、漏斗转化率——依赖 ticket 03 的阶段历史，5–20 条时百分比噪声大，A 首屏不放。
- **不做**：环形图/多图分析页；无阶段历史的回复率/Offer 率；横向看板作为主追踪界面（20 条时一屏只能看到 2–3 列）。
- **原型**：`.scratch/nextstep/prototypes/08-dashboard-prototype.html`；变体 A 默认打开，底栏切换「空 / 8 条 / 20 条」；最新捕获见分支 `worktree-dashboard-prototype-08-final`。
